# Implementation and results

Status as of this write-up: the planning layer of TaskFlux is implemented and tested against a step-level simulator. **No robot and no OpenVLA weights were used.** The development machine has a 4 GB RTX 3050 laptop GPU, which cannot hold the 7B model. Every number below comes from `taskflux/sim.py` with the assumed parameters stated there, and characterises the planning layer under those assumptions.

## How to run it

```bash
python -m pytest tests -q                  # 207 tests, about 2 s
python -m experiments.run_experiments      # full experiment suite, about 20 s, writes experiments/results/
python -m experiments.retention_toy        # adapter merge gate on a toy policy
python -m taskflux.demo                    # scripted operator dialogue on the gearbox example
```

Dependencies: Python 3.12, numpy, scipy, pandas, matplotlib, scikit-learn, torch (toy only), pytest. All were already present.

## Architecture

```
operator utterance ─► IntentClassifier (+ lexical stop override)      taskflux/utterances.py
                          │  P(clarification, edit, changeover, abort)
                          ▼
                     Triage: act / continue / ask / halt                taskflux/triage.py
                          │  Ra, Rc, Ca from the reconciler's cost-to-go
                          ▼
   ┌── act ──►  Reconciler: keep / undo / discard, refusal certificate  taskflux/reconcile.py
   │                salvage-versus-scrap decision
   └── ask ──►  Hedged execution: zero-regret steps while waiting       taskflux/hedge.py
                          │  one instruction per step
                          ▼
                     StepPolicy (SimPolicy here, OpenVLAPolicy stub)    taskflux/vla.py
```

| Module | Role |
|---|---|
| `process.py` | Step, variant and process model: `requires`, `covered_by`, irreversibility, undo damage risk, tools. Validates acyclicity and variant closure. |
| `reconcile.py` | The minimum undo closure, reverse-dependency undo order, forward plan, refusal certificate, plain-language explanation, scrap comparison, tool check. |
| `hedge.py` | Zero-regret step selection for the confirmation window. |
| `triage.py` | Cost-coupled decision rule, plus the fixed-threshold baseline. |
| `utterances.py` | Synthetic utterances with disjoint train, dev and test templates; a calibrated four-way classifier; the lexical stop override. |
| `controller.py` | The runtime glue that owns workpiece state, the queue, and the dialogue. |
| `adapters.py` | Known-versus-novel routing and the two-gate adapter merge. |
| `vla.py` | The seam to a VLA. `OpenVLAPolicy` follows the OpenVLA README usage and is **untested**. |
| `sim.py` | Step-level episode simulator, four baselines, TaskFlux, ask variants. |
| `synth.py`, `examples.py` | Random two-variant processes; the hand-authored gearbox. |
| `metrics.py` | Wilson intervals and mean confidence intervals. |

## Results

Full tables are in `experiments/results/results.md` (regenerated by the script). Headlines only here. Success intervals are 95% Wilson. "Success" counts a scrap-and-restart that ends in the right product, so `scrapped` and `destroyed` are shown beside it.

### E1. Changeover with the intent already known

| Stage of the change | What it means | Result |
|---|---|---|
| **Truncation only** (nothing to undo) | The new goal shares everything built so far. | **The reconciler adds nothing.** The naive replanner (B3a) matches TaskFlux: 99.7% against 99.4% success, 152 s against 153 s (gearbox, 1,500 episodes each). Restart and order-diff replanning lose time and sometimes damage the part. |
| **Undo required** | Completed steps conflict and must come off. | **TaskFlux 99.9%, rework 0.32, 162 s.** Restart 84.7%, rework 0.91, 310 s. Order-diff 83.7%, rework 0.79, 293 s. The naive replanner collides every time. TaskFlux does 0 unneeded undos; restart does 4.25 per episode (gearbox, 1,200 episodes each). Synthetic processes (7,584 episodes each): 92.7% against 90.1% and 74.0%, 260 s against 360 s and 334 s. |
| **Scrap cheaper than a risky salvage** | Expected damage makes a restart cheaper. | TaskFlux 99.3% (it scraps); restart 77.6%; order-diff 64.0%. Synthetic. |
| **Irreversible conflict** | A required undo crosses a cured or set step. | **TaskFlux matches restart** (99.7% against 100% on the gearbox; about 330 s each). Nothing beats scrapping here. The differences are behavioural: TaskFlux asks first and says what blocks the change, while order-diff replanning destroys the workpiece 100% of the time. |

### E2. Triage under classifier uncertainty (scored by the simulator, not by the decision formulas)

| Policy | Mean regret, s | Note |
|---|---|---|
| Oracle | 0.0 | ceiling |
| **TaskFlux** | **2.7 ± 0.1** | asks in 24% of cases |
| TaskFlux without hedging | 3.3 ± 0.1 | hedging is worth about 0.6 s per utterance |
| Fixed threshold 0.5 | 4.2 ± 0.2 | |
| Fixed threshold 0.3 (over-trigger) | 4.3 ± 0.2 | |
| Always ask, with hedging | 6.0 ± 0.0 | asks 92% of the time |
| Always ask, idle | 8.4 ± 0.0 | |
| Never act | 23.9 ± 0.4 | |

The classifier alone catches **88.5%** of stop requests on held-out phrasings; with the lexical override, 100% (with 0% false halts on this synthetic set). That gap is the reason a stop must never depend on a learned model. The 100% figure is not evidence about real speech.

### E3. Hedged execution

Worst-case change in completion time over 2,125 synthetic states plus the gearbox: **0.00 s** (never worse, in either world). A safe step exists in 44% of gearbox states and 73% of synthetic ones; average saving 2.7 s to 4.4 s per confirmation, bounded by the 6 s window. Time to the first useful action falls from 7.4 s to 4.5 s on the gearbox and to 2.6 s on the synthetic processes. This is a modest gain in seconds. Its value is that it is free of regret by construction.

### E4. Speed

Reconcile takes 0.025 ms at 9 steps and 14 to 17 ms at 800 steps (varies by run).

### E5. Sensitivity to the irreversible-step rate

TaskFlux is at or above both baselines on success and is faster than restart at every rate from 0 to 0.4. The order-diff replanner degrades sharply (destroyed part in 12% of cases at rate 0 and 79% at 0.4). At rate 0.4 TaskFlux and restart tie on success (98%).

### Retention gate (toy, not OpenVLA)

A small MLP with a LoRA adapter merges when the two variants do not conflict (retention 96% to 94%). With conflicting variants the gate refuses (95% to 74% and 96% to 40% if merged blindly) and the adapter stays routed. **Caveat that matters for the plan:** a conservative Wilson-bound gate needs about 36 to 57 evaluation episodes before it can pass even a perfectly retained variant. The evaluation protocol budgets 10 to 15. On a student-scale cell the gate will refuse to merge. That is safe, but merge-back can then only be validated in simulation.

## What the tests and the demo caught

Worth reporting, because each is a real modelling error that plausible aggregate numbers would have hidden.

1. **First hedging definition was not zero-regret.** A step can be physically ready yet cover something the running plan still needs first. Caught by the property test in `tests/test_hedge.py`.
2. **"Continue" looked free when the running product was finished**, so a certain changeover request was ignored. Caught by the scripted demo, not by the metrics. A missed changeover is only noticed after a delay, so idling through the delay is regret. Regression test added.
3. **"Act" looked free early in the build**, tying with "continue". Acting on a false changeover has the same discovery-delay cost as missing a real one. Both terms are now symmetric.
4. **Regret was first scored with the same formulas that made the decision**, which is circular. Regrets are now computed by the step simulator.
5. **A failed episode with time near zero was counted as the best response**, inflating every policy's regret and giving the oracle 10 s of regret. Failed or disallowed responses now count as infinite time.
6. **Acting wrongly for long enough can execute an irreversible step of the wrong product.** The simulator marked that as a failure; it is a scrap-and-restart, which is finite.
7. **Per-episode seeds used Python's randomised string hash**, so runs were not reproducible. Now deterministic.
8. **The gearbox ended on its irreversible step**, so no irreversible conflict occurred mid-build. A leak-test step after each adhesive fixed that.
9. **The classifier misses about 11.5% of stops.** The lexical override exists because of this finding.

## Threats to validity

* All timing and success figures rest on assumed parameters (`SimParams`, per-step costs, damage probabilities). Sensitivity is explored only for the irreversible-step rate.
* Reversibility, damage risk and costs are hand-set. The reconciler is only as good as that annotation.
* The utterances are authored by us and the classifier is trained and tested on the same generator, with disjoint templates. Real speech will be harder.
* The gearbox is one hand-built example. The synthetic processes are drawn from a generator whose settings we chose.
* The two-variant setting is the simplest one. Repeated changes and more than two variants are not evaluated.
* The comparison baselines are our own implementations of what an LLM replanner would do (B3a, B3b). No published system was reproduced.
* Undo is assumed to work at the stated probability. On a real cell it may be the binding constraint.

## Integrating with OpenVLA

`taskflux/vla.py` defines the seam. TaskFlux issues one language instruction per step and needs two things a stock OpenVLA does not provide: a **step-completion verifier** (OpenVLA has no termination signal) and **state kept outside the policy** (it sees one image and no history). `OpenVLAPolicy` wraps `predict_action` as documented in the OpenVLA repository, with 4-bit loading as an option. Before relying on it, check on the target machine that it loads, and confirm the prompt format and `unnorm_key` against the repository README. Neither was verified here.
